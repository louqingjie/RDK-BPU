## 第 1 章：先讲清楚问题是什么

### 1.1 自瞄的最后一公里

一个自瞄系统的完整链路是：

```text
相机拍照 → 找到装甲板 → 算出它的位置和姿态 → 控制云台指向它 → 开火
                          ↑
                    这一步叫 PnP 解算
```

"找到装甲板"这一步，现在大家都用神经网络（YOLO 类模型），效果很好、很稳。
但神经网络**只会告诉你 4 个角点大概在哪里，误差是"像素级"的**——就是说，它说角点在 (312, 457)，真实位置可能在 (313, 456)。

**问题就出在这里：PnP 解算对角点误差极其敏感。**

### 1.2 一个直观的例子

想象你拿一个长方形的名片，闭上一只眼睛看它：

- **卡片离你多远**：看它在你视野里显得多"大"。卡片显得越小，说明越远。
- **卡片朝向哪边**：看它左右两半的透视变形——朝向你转动时，靠近你的那半边会显得**稍微大一点**。

现在关键来了：

- 判断"多远"，靠的是卡片的**整体大小**，这个信号很强。卡片在 3 米处高约 37 像素，你的测量误差哪怕有 3 像素，也只是 8% 的误差。
- 判断"朝向哪边"，靠的是**左右两半的细微差别**。在 3 米处，卡片每转动 1 度，这个差别只有约 **0.036 像素**！

也就是说：**同样 3 像素的角点误差，测距离只错 8%，测朝向却可能错出几十度。**

这不是吓唬人，是我们实测的。用蒙特卡洛仿真（给理想角点加上 INT8 量化的噪声，再跑 PnP），结果如下：

| 距离 | 瞄准点误差 | 测距误差 | 朝向误差 |
|---|---|---|---|
| 3 m | **3.4 毫米**（几乎没问题） | 8.8%（0.26 m） | **22°~61°**（完全不可用） |
| 7 m | 7.5 毫米 | 17% | 30°~66° |

**瞄准还能用，测距会打飞远距离，朝向彻底废了。**

这就是为什么强队都在神经网络后面加一步"传统视觉精修"。

### 1.3 名词解释：什么叫"传统视觉精修"

"传统视觉"指的是不依赖神经网络、用数学和几何规则直接处理图像的方法，比如：

- **二值化**：把图片按亮度分成黑白两半，灯条是发光的，会变成一大块白
- **找轮廓**：在黑白图里勾勒出白色区域的边界
- **直线拟合**：一堆点里找一条最贴合的线

"精修"的意思是：神经网络先给个**粗略答案**，传统方法再在附近**重新精确测量一遍**。

## 第 2 章：PnP 到底在干什么

### 2.1 定义

PnP（Perspective-n-Point）解决的问题：

> **已知**一个物体在真实世界里的形状和尺寸（比如装甲板是 135mm × 55mm 的长方形），
> **已知**这个物体在照片里的 4 个角点像素坐标，
> **求**这个物体在相机坐标系里的 3D 位置和旋转姿态。

打个比方：你知道一张 A4 纸的实际大小，拍照后量出纸在照片里的 4 个角的位置，就能算出纸离你多远、歪了多少度。这就是 PnP。

OpenCV 里一行代码：

```cpp
cv::solvePnP(object_points, image_points, camera_matrix, dist_coeffs, rvec, tvec);
//  object_points : 3D 真实坐标（米）
//  image_points  : 2D 像素坐标
//  rvec / tvec   : 输出的旋转和平移 = 物体的姿态和位置
```

两家都用 `cv::solvePnP`，且都选了 **IPPE** 方法——这是专为**平面目标**设计的快速解法，装甲板正好是一个平面。

### 2.2 PnP 是一个"误差放大器"

PnP 本身没问题，问题在于它把输入误差**不均匀地放大**到不同输出上：

| 求解目标 | 对角点误差的敏感度 | 原因 |
|---|---|---|
| 位置（左右、上下） | **低**（误差 ≈ 像素误差 × 距离 ÷ 焦距） | 用的是 4 个点的平均位置，噪声互相抵消 |
| 距离（远近） | **中**（误差 ∝ 距离的平方） | 靠目标"显得多大"反推，越远目标越小，同样的像素误差占比越大 |
| 朝向（yaw / pitch） | **极高** | 靠左右两半的透视不对称反推，信号本身极微弱 |

记住这个表，后面两家方案的设计都是围绕它展开的。

### 2.3 朝向为什么这么病态

"病态"是数学术语，意思是：**输入的微小变化导致输出的巨大变化**。

装甲板朝向的信息藏在哪？藏在"左边缘和右边缘的透视差异"里。我们算过：

> 3 米处的小装甲板，每转 1°，左右边缘的视差变化只有 **0.036 像素**。
> 而神经网络的角点误差动辄 1~3 像素，INT8 量化后能到 ±6 像素。

用 0.036 像素的信号去对比 3 像素的噪声，就像用体温计去量一杯被扔了石子的水——**信号被噪声完全淹没**。

这就是 PnP 的"正对病态"：目标正对相机时（yaw≈0），这个信号最弱，误差最大。而正对恰恰是比赛里最常见的射击姿态。

**两家都意识到了这个问题，但解法不一样**——后面第 4、5 章分别讲。

## 第 3 章：上科大 SHtech 的传统精修

### 3.1 项目背景

- 平台：**AX650**（ARM 架构，18 TOPS，算力有限）
- 主流程：`Sensor → Preprocess → Detect → CornerRefine → Predictor → Planner`
- README 明确写着：**`CornerRefine`：使用传统视觉方法精修灯条和角点**
- 实战成绩：无人机远距离打击，南部赛区顶级数据

核心文件：`detect/armor_corner_optimizer.cpp`。

### 3.2 精修的七步流程

输入：**原始图像** + 网络输出的 4 个角点。
输出：精修后的 4 个角点（或者"放弃"，表示精修失败）。

**第 1 步：从网络角点反推两条灯条的几何**

装甲板左右各有一条发光的灯条（竖直的长条）。网络的 4 个角点正好是两条灯条的端点，所以可以直接算出：

```cpp
left_center  = (corner[0] + corner[1]) / 2    // 左灯条中点
right_center = (corner[2] + corner[3]) / 2    // 右灯条中点
left_height  = |corner[1].y - corner[0].y|    // 灯条高度（像素）
tilt_angle   = 灯条与竖直方向的夹角
```

灯条长度还会被**强制限定**在 10~120 像素之间——防止网络偶尔给出离谱的值，把后续搜索带偏。

> 这里体现了第一个设计思想：**网络输出只用来"估计大概"，所有数值都还会被再次校验**。

**第 2 步：给每条灯条开一个"搜索区域"（ROI）**

```cpp
roi_height += light_length × 0.5    // 上下各扩 50% 灯条长度
roi_width  += light_length × 0.5    // 左右各扩 50%
```

ROI（Region of Interest，感兴趣区域）就是"在这一小块区域里找"。尺寸跟着灯条自适应，最小 20×20 像素。

如果 ROI 贴到了图像边缘，直接放弃精修——因为边缘截断会导致测量不准。

> 这一步回答了"网络误差可以有多大"：ROI 半高是灯条高度的 0.75 倍。3 米处小装甲板灯条高 37 像素，容许误差 ±28 像素——而 INT8 量化误差只有 ±6 像素，**占容差的 22%**。他们的配置里甚至写着一个参数 `position_error_ratio = 0.5`，注释是"位置可能偏离半个高度"——**设计时就按网络误差很大来兜底**。

**第 3 步：ROI 内二值化**

把这一小块图变成黑白：亮的（灯条）变白，暗的（背景）变黑。

```cpp
cv::cvtColor(roi_img, gray, COLOR_RGB2GRAY);   // 转灰度
cv::threshold(gray, binary, 104, 255, THRESH_BINARY);  // 阈值 104
```

细节：**红方和蓝方用不同的阈值**。红灯条和蓝灯条的亮度不一样，用同一个阈值会一边过曝一边看不见。他们在代码里按敌方颜色切换 `bin_threshold_for_red` / `for_blue`。

**第 4 步：找灯条——精度就藏在这一步**

```cpp
cv::findContours(binary, contours, ...);       // 找出所有白色区域的轮廓
// 过滤太小的轮廓
// 填充率检查：白色像素占外接矩形面积 > 0.5，确保是实心条状而非杂乱噪声
cv::fitLine(points, line_params, cv::DIST_L2, ...);   // ★ 关键：对所有像素做直线拟合
```

**`cv::fitLine` 是整个方案的精度来源。**

对比一下两种做法：

| 做法 | 用的信息 | 精度 |
|---|---|---|
| 直接取轮廓的两个端点 | 2 个像素 | 像素级，误差 ±1 像素起步 |
| **对所有轮廓内像素做最小二乘拟合** | **成百上千个像素** | **亚像素**，误差远小于单个像素 |

一条灯条在 3 米处有几百个像素点。对这些点拟合一条直线，单个像素的噪声被平均掉，端点位置自然精确到亚像素。**这是神经网络回归两个坐标点根本做不到的**——网络每个输出就是 1 个数，没有"平均"可言。

拟合出直线后，让直线和搜索框的上下边界相交，得到灯条的 top 和 bottom——这就是精修后的角点。

**第 5 步：挑出真正的灯条**

ROI 里可能不止一条灯条（比如旁边有别的发光物体）。用加权打分选最好的：

```cpp
score = 中心距离 × 0.2 + 长度差异 × 0.7 + 角度差异 × 0.1
// score > 0.3 → 判定不匹配，拒绝使用
```

**长度权重最大（0.7）**。为什么？因为长度最稳定——灯条物理尺寸固定，只要距离不变，它在图像里的长度就不该变。而位置可能因为网络误差偏一点，角度受拍摄角度影响。**用最可靠的量做主要判据**，这是很成熟的工程判断。

**第 6 步：左右一致性校验**

两条灯条物理上是同一个装甲板上的，理应长度接近、角度接近：

```cpp
if (左右长度比 < 0.7 || 左右倾角差 > 5°)  →  放弃精修
```

防止"一侧检到真灯条、另一侧检到噪声"的组合骗过筛选。

**第 7 步：回退机制（在 corner_refine_submodule.cpp）**

```cpp
if (refined_corners.has_value()) {
    bbox.pts[i] = refined[i];                      // 精修成功，用传统结果
    bbox.source = DetectionSource::TRADITIONAL;
} else {
    bbox.source = DetectionSource::NEURAL_NETWORK; // 失败，保留网络角点
}
```

**精修失败不丢目标，回退到网络角点。** 两套结果都保留来源标记，方便调试时统计成功率。

### 3.3 上科大方案小结

一句话：**网络给"大概在哪"，传统方法给"精确在哪"，失败就退回网络结果。**

精度关键点：`fitLine` 对全部像素做最小二乘拟合 → 亚像素。

## 第 4 章：同济 sp_vision_25 的传统精修

### 4.1 项目背景

- 平台：**NUC12 迷你主机（i7-1260P，x86）+ OpenVINO**，算力相当充足
- 相机：海康 **MV-CS016-10UC + 6mm 镜头**——**和我们项目完全同款**
- 识别器：25 赛季从传统图像处理**换成了**神经网络四点检测模型（深圳大学 RobotPilots、北科大 Reborn 开源）
- 实战成绩：国赛步兵最高命中率 **39.6%**，正常发挥不低于 30%；2 米处 300 血、14 rad/s 旋转靶击杀时间约 10 秒

**注意一个重要事实：他们算力充足、跑在 x86 上，仍然做了传统精修。** 这说明精修不是为了弥补算力不足，而是角点精度的固有问题。

### 4.2 精修逻辑（detector.cpp 的精修重载）

和上科大思路相同，实现细节不同：

**第 1 步：构造放大 ROI**

利用现有角点沿灯条方向向外延展（0.75 倍缩放系数计算新角点），再用 `minAreaRect` → `boundingRect` 得到搜索区域。ROI 超出图像就放弃。

**第 2 步：ROI 内重新做一遍完整的传统检测**

灰度化 → 二值化 → `findContours` → 灯条几何校验（角度误差、长宽比、最小长度）。这一步和上科大几乎一样，区别是他们**直接用灯条端点作为角点**，没有做 fitLine 亚像素拟合。

**第 3 步：最近端点匹配**

对 ROI 内每个灯条，计算其上下端点与原始角点的距离之和，分别选出最匹配的左右灯条。也就是"谁离网络说的位置最近，谁就是那条灯条"。

**第 4 步：15 像素门限**

```cpp
if (min_distance_br_tr + min_distance_tl_bl < 15) {
    armor.points[0..3] = 匹配到的灯条端点;   // 采纳精修结果
    return true;
} else {
    return false;   // 保留原角点
}
```

这是一个**一致性校验**：如果传统方法找到的灯条和网络说的位置差得太远（加起来超过 15 像素），说明两者很可能看的是不同的东西，此时不信任何一方，保留原角点。

**第 5 步：保留了一条被注释掉的更精细方案**

```cpp
// lightbar_points_corrector(lightbar, gray_img);  // 关闭PCA
```

这个函数基于"质心 + PCA 对称轴 + 亮度跳变搜索"做亚像素修正。**实测后被关闭了**——这是一个很有价值的信号：更复杂的方法不一定更好，他们在实车上验证后选择了简单方案。

### 4.3 顺带一提：他们没有用标准 NMS

神经网络方案里通常有 NMS（非极大值抑制，去掉重叠的检测框）。同济的传统检测器里**没有**，而是用"共用灯条去重"替代：两个装甲板如果共用同一条灯条，只保留图案更清晰/置信度更高的那个。这在功能上等价，但更符合装甲板的物理结构。

## 第 5 章：同济的 yaw 网格搜索——针对"正对病态"的第二板斧

### 5.1 问题回顾

第 2.3 节说过：PnP 解朝向依赖左右透视不对称，3 米处每 1° 只有 0.036 像素的信号。即使角点做到了亚像素，**这个信号本身也太弱了**。

上科大没有专门处理这个问题（精修后的角点精度已足够高）。
同济则加了一道**独立的 yaw 优化**。

### 5.2 他们的做法（solver.cpp 的 `optimize_yaw`）

**核心思想：既然朝向这么难测，那就换个思路——不直接解，而是"猜"。**

```text
以云台当前 yaw 为中心，±70° 范围、步长 1° 暴力搜索（共 140 个候选值）

对每一个候选 yaw：
    1. 固定装甲板的位置（位置是可信的，见第 2.2 节：位置误差只有毫米级）
    2. 假设装甲板的 pitch（俯仰角）是 ±15°
       —— 哨兵前哨站是 -15°，其他都是 +15°，这是比赛规则决定的固定安装角
    3. 用"位置 + 假设 pitch + 候选 yaw"构造出装甲板的完整姿态
    4. 把 4 个角点重投影回图像
    5. 计算重投影误差（投影位置与实际角点的像素距离之和）

取重投影误差最小的候选 yaw 作为最终结果。
原始 PnP 的 yaw 保存到 yaw_raw 备用。
```

### 5.3 为什么这一招有效

**关键洞察：yaw 是病态的，但"位置 + 假设 pitch"不是。**

- 装甲板的 pitch 在比赛里是**已知常量**（规则规定装甲板倾斜 15° 安装）——不用测，直接假设
- 装甲板的位置由 PnP 给出，误差只有毫米级——足够可信
- 于是整个姿态里**只剩一个未知数 yaw**

一个未知数，就可以暴力搜索：把 140 个候选 yaw 逐个代入，看哪个"猜出来的角点投影"和实际看到的角点最吻合。

**这相当于把一个病态的连续优化问题，变成了一个简单的一维查表问题。**

代价：140 次重投影，每次只投影 4 个点，在 ARM 上也是微秒级，可以忽略。

细节：

- 平衡步兵（3/4/5 号大装甲）**跳过** yaw 优化，代码注释说明"平衡不做 yaw 优化，因为 pitch 假设不成立"——平衡步兵的装甲板不倾斜 15°，假设不成立，强行优化反而错
- 他们还写了一个更复杂的 `SJTU_cost()` 代价函数（结合线段长度差、端点位移、夹角），但**也被注释掉了**，实际用的就是最简单的像素距离和。和上科大关掉 PCA 修正一样：**实车验证后选了简单方案**

### 5.4 一个容易被忽略的点：重投影误差是"验算"

重投影误差（reprojection error）是整个体系里的通用校验手段：

> 把你算出来的 3D 位姿，重新投影回图像，看和实际检测到的角点差多少。

它既能用来挑最优解（同济的 yaw 搜索），也能用来评估解算质量。如果重投影误差很大，说明这次解算不可信，应该丢弃。

## 第 6 章：两家方案对比

| | 上科大 SHtech | 同济 sp_vision_25 |
|---|---|---|
| **平台** | AX650（ARM，18 TOPS） | NUC12 i7-1260P（x86） |
| **相机** | — | 海康 MV-CS016-10UC + 6mm（与我们同款） |
| **网络角色** | 出候选框 + 粗角点 | 出候选框 + 粗角点 |
| **传统精修** | ROI 内 `fitLine` 最小二乘拟合（**亚像素**） | ROI 内重新提灯条 + 最近端点匹配（**像素级**） |
| **采纳门限** | 加权 score > 0.3 拒绝 | 端点距离和 < 15 px |
| **一致性校验** | 左右灯条长度比、倾角差 | — |
| **失败回退** | 保留网络角点，标记来源 | 保留原角点 |
| **yaw 处理** | 未专门处理 | **±70° 网格搜索 + pitch 假设 ±15°** |
| **被弃用的复杂方案** | — | PCA 亚像素修正、SJTU 代价函数 |
| **装甲板尺寸** | — | 灯条 56mm、大装甲 230mm、小装甲 135mm |

两家的差异很有意思，恰好互补：

- **上科大在角点测量上做文章**（fitLine 亚像素），把输入误差压到最低
- **同济在解算方法上做文章**（yaw 网格搜索），承认输入有误差，改用更鲁棒的解法
- **理想的完整方案是两者都做**

而他们的**共同点**更值得注意：

1. 网络只负责"哪里有、是什么"，**不负责精确坐标**
2. 传统方法在**原始分辨率**上工作，不受网络输入缩放影响
3. 都有**失败回退**，精修不成功就退回网络结果，绝不丢目标
4. 都在实车上**砍掉了复杂方案**，留下的都是简单可靠的

## 第 7 章：论证——"网络角点只做粗定位"是行业共识

把证据摆在一起：

**证据一：算力充足的项目也做精修**

同济跑在 x86 的 i7 上，有 OpenVINO 甚至 GPU 推理可选，完全有算力直接用网络角点。他们仍然做了精修 + 15 像素门限 + yaw 网格搜索。**说明这不是算力问题，是精度属性的固有问题。**

**证据二：设计参数明确假设网络误差很大**

上科大的配置里写着 `position_error_ratio = 0.5`，注释是"位置可能偏离半个高度"。换算过来：3 米处小装甲板灯条高 37 像素，容许偏差 ±18 像素。**他们设计时就按网络误差很大来兜底**，ROI 开得足够宽。

**证据三：两家独立得出相同架构**

一个在 ARM 上（算力紧张），一个在 x86 上（算力充裕）；一个用 fitLine 亚像素，一个用灯条端点 + yaw 搜索。**路线和细节完全不同，但"网络出粗定位 + 传统方法出精确角点"这个架构完全一致。** 独立收敛到同一结论，这比任何单一案例都有说服力。

**证据四：量化误差的定量核算**

用我们的实测数据核对：INT8 量化后角点误差约 ±6.2 像素（原图坐标）。

| 场景 | 上科大 ROI 容差 | INT8 误差占比 |
|---|---|---|
| 小装甲板 3 m（灯条高 37 px） | ±28 px | 22% |
| 小装甲板 5 m（22 px） | ±17 px | 37% |
| 小装甲板 7 m（16 px） | ±12 px | 52% |
| 大装甲板 7 m（37 px） | ±28 px | 22% |

**INT8 的误差全部落在精修的容差范围内，最紧的工况也只占 52%。** 换句话说：只要走精修链路，网络角点用 INT8 绰绰有余。

**证据五：反例验证——如果不用精修会怎样**

7.5 节的仿真给出了反面教材：把 INT8 角点**直接**喂给 PnP，测距误差 3%~19%、朝向误差 12°~66%。5 米处弹道补偿会算错约 52 毫米，超出装甲板半高 27.5 毫米——远距离必打飞。

**正反两面都验证了：精修不是锦上添花，是必需品。**

## 第 8 章：对我们方案的启示

### 8.1 结论

| 方案 | 网络角点精度要求 | 量化方案 |
|---|---|---|
| **网络 kpt 直接做 PnP**（不推荐） | 亚像素级 | 必须 INT16 或坐标相对化 |
| **网络出候选 + 传统精修（推荐）** | 粗定位即可（±10 px 量级） | **INT8 就够** |
| 两者融合 | 粗定位 + 鲁棒性备份 | INT8 |

我们的推荐：**沿用"网络出候选 + 传统方法精修角点"的架构**。这样：

- 量化的重点变成**检测召回率和分类准确率**（这两项对量化最鲁棒：类别分数步长 0.007，可分辨 125 级）
- `kpt` 分支退化为"给精修提供 ROI"，INT8 完全够用，不需要 INT16
- 7.5 节担心的坐标精度问题自然消解

### 8.2 建议移植的三个组件

1. **精修器**：建议以上科大的 `fitLine` 版本为蓝本（精度更高），结合同济的"15 像素门限"思路做一致性校验
2. **yaw 网格搜索**：同济这招强烈建议抄。成本几乎为零，直接解决"正对时朝向不可用"的问题。注意平衡步兵（3/4/5 号大装甲）要跳过
3. **双源回退**：精修失败保留网络角点，并记录来源标记，方便统计成功率、定位问题

### 8.3 需要核对的坑

**角点顺序**。上科大代码里右灯条是反着写的：

```cpp
optimized_corners[3] = right_lights[best_idx].top;    // index 3 = 右上？
optimized_corners[2] = right_lights[best_idx].bottom; // index 2 = 右下？
```

即他们的顺序是 `(左上, 左下, 右下, 右上)`——**逆时针**。而我们模型包 README 写的是"4 个角点顺时针排列"。两边约定很可能不一致，**对接前必须先用 `preview.py` 可视化核对**，否则 PnP 会解出镜像姿态，表现为"云台往反方向偏"，这种 bug 极难排查。

### 8.4 不要过度迷信精修

传统灯条方法依赖灯条**发光**。三种情况会失效：

- 远距离灯条太暗，二值化提不出来
- 曝光压低时（打远距离必须压曝光）灯条对比度下降
- 灯条被遮挡或侧向角度太大

而网络 kpt 不依赖灯条，鲁棒性更好。所以两者是**互补**的：精修可用时用精修（精度高），不可用时回退网络角点（鲁棒）。**这正是保留 kpt 分支并把它量化好的价值**——不是所有帧都需要它，但失效的那些帧里它是唯一的依靠。

## 附：名词速查

| 名词 | 含义 |
|---|---|
| **PnP** | 已知物体真实尺寸 + 图像中的角点位置，反求物体的 3D 位置和姿态 |
| **重投影误差** | 把算出的 3D 位姿重新投回图像，与实际角点的像素偏差。越小越可信 |
| **亚像素** | 精度高于 1 个像素。通过对大量像素做数学拟合获得 |
| **`fitLine`** | OpenCV 的最小二乘直线拟合函数，对一堆点找最贴合的直线 |
| **ROI** | 感兴趣区域，只在图像的一小块里做处理，省时且抗干扰 |
| **病态问题** | 输入的微小变化导致输出的巨大变化 |
| **PCA** | 主成分分析，这里用来找灯条的对称轴 |
| **IPPE** | 一种专为平面目标设计的快速 PnP 解法 |
| **二值化** | 按亮度把图分成黑白两半，灯条会变成一块白 |
| **回退（fallback）** | 主方案失败时使用备用方案，保证系统不中断 |
